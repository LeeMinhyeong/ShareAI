# ADR 0009: 강제 종료 기한과 데이터베이스 소유권

## 상태

부분 구현. 앱 전체 요청 소유권과 drain은 아직 연결되지 않았으며 Phase 4 운영 적용은 금지한다.

## 결정

종료 제한시간에 여전히 비동기 작업이 실행 중일 수 있으므로 명시적으로 데이터베이스를 닫지 않고 비정상 종료 코드로 프로세스를 종료한다. 운영체제가 프로세스의 자원을 회수한다. 이는 작업이나 토큰 회전의 완료, graceful shutdown 또는 손실 없는 종료를 보장하지 않는다. 불확정 외부 작업은 기존 durable fence 정책에 따라 처리한다.

등록된 drain이 모두 성공해도 앱의 모든 DB 생산자가 추적됐다는 뜻은 아니므로, 현재 임시 방어로 정상 drain 후에도 공유 DB와 격리 writer 연결을 명시적으로 닫거나 재정리하지 않는다. 5초 기한은 유지하되 `unref()`하여 다른 활성 핸들이 없으면 프로세스가 자연 종료할 수 있게 한다. 활성 핸들이 남으면 기한 콜백은 실패 종료를 시도한다. drain 실패 시 기한은 참조된 상태로 유지한다. 이는 프로세스가 살아 있는 동안 추적되지 않은 작업에 대한 조기 DB close를 피하기 위한 조치이지 전체 작업 완료의 보장이 아니다. 활성 핸들이 없는 pending Promise만으로 프로세스는 유지되지 않고, 살아 있는 작업도 5초 기한에서 중단될 수 있다. 명시적인 DB close나 WAL checkpoint, 강제 종료에 대한 내구성은 보장하지 않는다.

정상 종료에서 DB를 안전하게 닫으려면 HTTP ingress, Express 오류와 지연 dispatch, 모든 인증·라우트 및 응답 후 작업, 독립 refresh와 OAuth/SIWC callback 및 시작·종료 작업을 검증된 소유권 경계로 추적해야 한다. `server.ts`는 종료 제한시간을 먼저 설정하고, 외부 로그나 stop 훅을 호출하기 전에 새 요청 작업과 토큰 갱신의 진입을 닫는 drain을 각각 시작하도록 부분 연결됐다. 각 drain 시작이 실패하면 해당 진입이 닫혔다고 가정하지 않고 DB close를 막는다. 등록된 갱신 작업은 실제 promise가 끝날 때까지 기다리지만 `allSettled`는 저장 성공을 보장하지 않는다. 이 장벽은 등록된 작업만 포함하며 전체 경계가 아니다. 연결 종료만으로 해당 작업이 완료됐음을 증명할 수 없으므로 정상 종료 경로 전체가 안전하다고 주장하지 않는다.

서버가 기동된 후 HTTP 리스너에 치명적 오류가 생길 수도 있으므로, fatal 경로에서도 5초 기한을 먼저 설정한 뒤 OAuth와 SIWC의 중단 함수를 각각 호출한다. 다른 stop 훅이 동기적으로 던지거나 비동기로 거부해도 나머지 호출은 시도하며, 오류를 외부에 상세 출력하지 않는다. 이 경로는 중단 완료를 기다린 뒤 정상 종료하는 방식이 아니라 기존 실패 종료와 연결 유지 정책을 보존한다. 합성 리스너 오류·합성 stop 훅 회귀는 호출·실패 격리·기한 순서만 확인했으며 실제 보조 리스너 종료, 모든 작업 완료 및 훅 사이 원자적 진입 차단은 보장하지 않는다.

SIWC 로그아웃은 첫 DB 작업과 원격 폐기 이후에도 최종 DB 검증을 수행한다. 기존에는 해당 핸들러가 `stopSiwc()`의 active 집합에 등록되지 않아 첫 writer 대기 중 stop이 먼저 완료될 수 있었다. 이제 로그아웃 시작 전에 전체 핸들러 promise를 등록하고 종료 시작 후 신규 로그아웃을 503으로 거부한다. 합성 writer를 사용하는 직접 핸들러 테스트에서 두 writer 대기와 응답 호출 시점의 소유권을 확인했다. 테스트는 관찰을 위해 VM에서만 stop resolver와 active 집합을 계측하며 실제 DB 쓰기·HTTP 인증·소켓 전달·원격 폐기는 검증하지 않는다. 서버의 5초 강제 종료가 작업을 중단할 수 있고, 이 수정은 다른 SIWC 관리자 경로나 모든 DB producer를 포괄하지 않는다.

SIWC 계정 목록, 라우팅 설정 조회·변경, 접근 정책 조회·변경의 다섯 동기 DB 핸들러도 인증 후 기존 SIWC active 집합에 등록한다. 종료 후에는 핸들러를 시작하지 않고 503을 반환하며, 동기 예외는 기존 Express 오류 전달 경로로 넘긴다. 합성 DB의 `getDb` 호출에서 stop을 동기 재진입시키는 시험으로 등록·응답 호출 시 소유권 및 종료 후 거부를 확인했다. 이는 모의 재진입이며 실제 운영에서 해당 재진입이 발생했다는 의미는 아니다. 인증·SQLite·소켓·다른 경로와 전역 drain의 안전성은 이 시험으로 입증되지 않는다.

관리자 DB 경로는 인증 후 각 동기 핸들러에 명시적인 작업 소유권을 부여하는 방향으로 부분 변경했다. 종료 시작 이후 지연 전달된 요청은 DB 접근 전에 거부하고, 이미 허용된 동기 작업은 핸들러와 응답 처리 반환까지 소유권을 유지한다. 사용자 관리, 계정 생성·목록, 설정 조회·전략 조회·전략 변경, 통계 조회와 라우팅 상태 조회 경로는 독립 정적 리뷰 후 합성 회귀 검증을 받았다. 라우팅 상태 조회의 일부 SIWC 상태·scope·갱신 시각 분기는 실제 저장소 검증 코드를 모의 DB·복호화와 함께 사용해 확인했으나, 실제 SQLite·암호화·SIWC 로그인 및 모든 unknown-state 경로는 검증하지 않았다. 이 검증은 모의 DB와 응답을 사용하며 실제 SQLite·소켓 또는 모든 서버 생산자의 종료 안전성을 증명하지 않는다. 계정 상세·수정·삭제 경로에도 인증 후 동기 작업 소유권을 연결했다. 사용자 제공 테스트의 수정 전 결과는 3/9 통과였고, 수정 및 별도 정적 리뷰 이후 집중 테스트는 모의 저장소·응답으로 15/15 통과했다. 응답 전송 오류 시 중복 응답을 시도하지 않는 사례를 포함한다. 실제 SQLite와 소켓 종료는 이 집중 테스트의 범위 밖이다. 계정의 나머지 경로, 관리자 비동기 작업, 파서와 다른 DB 생산자에도 이 보장이 적용됐다고 가정하지 않는다.

이 접근의 대가는 종료 중 관리 요청에 503을 반환하는 것이다. 추적된 작업이 남거나 drain 실패가 확인되면 제한시간에 실패 종료하는 쪽을 택한다. 추적되지 않은 작업은 이 장벽만으로 감지할 수 없다. 동기 콜백 반환은 그 콜백이 별도 DB 작업을 예약하지 않는다는 확인이 있을 때만 완료의 근거로 삼으며, 응답 실패가 이미 실행된 DB 쓰기의 롤백이나 안전한 재시도를 의미하지 않는다.

## 계정 가져오기와 OAuth 종료 결정

계정 가져오기는 관리자 인증 후 핸들러 루트에서 동기 소유권을 획득하고, 자격증명 파싱과 `getDb`, 암호화 및 계정 생성 전에 종료 중 진입을 거부한다. 핸들러의 파서·저장소 예외에 대한 고정 400 응답은 유지한다. 초기화 경로 감사에서 `getDb`, SQL 및 SIWC 저장소 초기화는 동기이며 비동기 Pino transport는 출력만 담당한다. 단, 외부 계측이 로거 또는 stdout을 DB 콜백으로 대체하지 않는다는 가정에 한정된다. 실제 초기화·마이그레이션·SQLite·암호화는 테스트하지 않았다.

OAuth 완료 작업의 promise는 `runCompleteFlow` 호출 전에 등록해 동기 재진입에도 소유권이 보이도록 한다. stop은 이미 수락된 완료 콜백과 bootstrap 경로를 기다리고, stop 이후 선택적 Claude bootstrap을 새로 시작하지 않는다. `onTokens` 성공 후 stop이 flow 맵을 비워도 `finishLogin`은 소유 중인 flow의 공개 스냅샷을 반환한다. 합성 시계 장애로 발생한 정리 예외는 정제하며 마지막 정리는 best effort로, 계정 저장 완료를 실패 또는 재시도 가능 결과로 바꾸지 않는다. 이 시계 장애 주입은 정상 운영에서 관찰된 장애가 아니다.

## 검증 범위 및 승인 대기

계정 가져오기 경로는 독립 정적 리뷰에서 확인했으나 합성 비밀값 검사와 정리 미완료로 인수 리뷰는 FAIL이다. 관리자·평문 마커를 연결하는 테스트의 Python 쓰기는 승인 대기이므로 수행하지 않았다. OAuth 테스트는 합성 환경만 사용했고 최신 부분 수정 후 개발 실행은 23/23이었으나, 무한정 지속될 수 있는 teardown과 초기 unhandled rejection으로 리뷰는 FAIL이다. 이후 부분 수정이 시도됐지만 helper를 시나리오에 연결하는 작업은 승인 대기이며 최종 검증이나 리뷰 통과를 뜻하지 않는다. 실제 provider 재진입은 입증되지 않았고 실제 provider·리스너·DB·암호화도 테스트하지 않았다. 구현 완료 전 실제 provider를 사용하지 않는다는 요청을 유지한다. Phase 4와 전체 DB 생산자의 안전성은 여전히 입증되지 않았다.

합성 VM의 서버 모듈 테스트는 등록된 drain이 완료된 뒤 메모리 SQLite에 대한 늦은 합성 쓰기를 확인했다. 별도 자식 프로세스 테스트는 실제 Node 타이머와 메모리 SQLite를 사용해 유휴 상태의 자연 종료와 활성 핸들이 있을 때 5초 기한의 실패 종료를 확인했다. SIGTERM과 서버 의존성은 모의이며, 운영 DB, OS 신호 전달, 전체 drain, 체크포인트 또는 실제 서비스는 검증하지 않는다.
