# ADR 0003: SIWC 로그아웃과 토큰 회전 경합

- **상태:** 채택 — 구현 및 검증 필요
- **작성일:** 2026-10-29
- **범위:** Phase 3 SIWC 세션 종료

## 배경

공유 설정을 비활성화하는 것과 OAuth 세션을 종료하는 것은 다르다. SIWC refresh 요청이나 재인증이 진행 중일 때 로컬 자격증명을 삭제하기만 하면 이전 작업이 회전된 토큰을 다시 저장할 수 있다. SQLite와 OpenAI 간의 작업은 하나의 원자적 트랜잭션으로 묶을 수 없으며, 중단·응답 유실이 발생하면 원격 세션의 실제 상태는 불확실할 수 있다.

## 결정

1. 로그아웃 시작 시 SQLite 쓰기 트랜잭션에서 계정 사용을 차단하고 자격증명 세대를 갱신한다. 인증된 관리자의 명시적인 후속 재인증 전까지 신규 선택·추론·refresh를 거부한다.
2. 이미 시작한 refresh와 재인증은 같은 영속 세대에 묶고, 로그아웃 이후 응답이 도착하더라도 이전 세대의 토큰을 저장하지 못하도록 조건부 저장한다. 서버 프로세스가 여러 개여도 같은 DB의 새 구현을 사용해야 한다. 이미 전송된 추론은 취소를 보장하지 않는다.
3. 해당 등록의 최신으로 알려진 refresh token에 대해 OpenAI의 discovery에 명시된 폐기 엔드포인트로 폐기를 시도한다. endpoint의 신뢰 경계와 리다이렉트를 검증하고 제한시간을 둔다. 취소·회전의 결과가 불확실할 수 있으므로 원격 폐기 성공을 과장하지 않는다.
4. 로컬 토큰은 제거하고 등록의 검증된 identity·client ID는 재인증을 위해 보존한다. 원격 폐기 성공이 명확하고 더 최신 회전 토큰이 생겼을 가능성이 없을 때만 확인 성공으로 표시한다. 통신 장애 또는 진행 중이던 refresh·재인증의 원격 결과가 불확실하면 원격 폐기 미확인으로 표시한다.
5. 진행 중 또는 중단된 로그아웃은 재시작 이후에도 사용 불가 상태를 유지한다. 필요한 관리자 재시도·재인증의 조건을 명확히 한다. 다른 계정과 사용 이력은 보존한다.

## 대안과 결과

- **공유 비활성화만 사용:** 토큰 저장 및 원격 세션이 유지되므로 로그아웃으로 채택하지 않는다.
- **원격 revoke 성공만 기다린 뒤 로컬 삭제:** 네트워크 중단 동안 로컬 접근이 유지되고 경합이 생길 수 있어 채택하지 않는다.
- **무조건 원격까지 완료했다고 표시:** 분산 작업 실패를 감추므로 채택하지 않는다.

SQLite 기반 세대 관리·사용 차단과 UI 상태 표기가 필요하며, 모든 프로세스가 해당 구현을 사용하는 운영 조건이 있다. 이 결정은 이미 요청된 추론의 즉시 중단이나 공급자 세션의 무조건적 원격 폐기를 보장하지 않는다.

## 검증 기준

격리 DB와 모의 OpenAI를 사용해 정상 종료, revoke 실패·timeout, 진행 중 refresh·재인증, 프로세스 간 경합, 충돌 시 세대 변경, 종료 중 재시작, 다른 계정 및 이력 보존, 비밀 미노출을 검증한다. 사용자에게 원격 결과의 확인 여부를 표시한다. 별도 에이전트 코드 리뷰 후 최종 테스트를 수행한다. 실제 서비스는 별도 계정 소유자 승인과 테스트로 확인한다.

## SQLite 경합의 현재 한계

SIWC 스키마 생성과 기존 열 추가는 DB 초기화의 쓰기 트랜잭션에서 수행하며, 채팅 요청에서는 초기화 없이 저장소를 연다. 독립 저장소 사용자는 기본 생성자로 초기화할 수 있다. refresh는 유한한 양의 제한시간만 받아들이며, 0이나 취소된 호출은 공유 작업이나 영속 claim을 만들지 않는다.

단, 실제 HTTP 경로 전체가 비차단이라는 보장은 아직 없다. 인증의 quota 예약은 기본 연결의 동기 쓰기 트랜잭션이며, SIWC 추론 시작의 fencing과 사용 이력 기록도 동기 쓰기를 수행한다. 다른 프로세스가 SQLite 쓰기 잠금을 보유하면 이 단계들이 이벤트 루프를 지연할 수 있다. 각 단계에서 quota 원자성·로그아웃 fencing 및 이력 정책을 보존하면서 비차단 처리하는 설계와 실제 HTTP 취소·시간제한 검증이 필요하다.
