# ADR 0002: 계정 풀 공유 범위와 사용자 접근 제어

- **상태:** 채택 — 구현·검증 필요
- **작성일:** 2026-10-29
- **범위:** Phase 3 SIWC 계정 접근 및 계정 풀 통합, Phase 4 선택 전략

## 배경

ShareAI는 관리자가 여러 구독 계정을 2~5명의 사용자에게 공유하도록 구성하는 제품이다. 모든 사용자를 계정별로 강제로 고립시키는 것은 이 목표에 맞지 않는다. 동시에 인증된 사용자가 다른 계정의 ID만 알아도 관리자의 공유 설정과 무관하게 해당 자격증명으로 요청할 수 있다면 의도하지 않은 계정 사용이 발생한다.

기존 계정 풀의 사용자별 접근 정책 및 별도 SIWC 저장소 통합은 확인과 구현이 필요하다. 기존 SIWC 계정의 권한 부여 대상을 데이터만으로 안전하게 추정할 수 없다.

## 결정

1. **관리자가 계정 공유 범위를 명시적으로 제어한다.** 전체 사용자에게 공유하는 옵션을 제공해 제품의 일반적인 소규모 공유 목적을 지원한다. 필요한 경우 특정 사용자에게만 허용하는 정책을 지원한다.
2. **새로 등록하거나 기존 SIWC 저장소에서 가져온 계정은 명시적 공유 설정 전에는 일반 사용자에게 노출하거나 선택하지 않는다.** 기존 자격증명은 그대로 보존하고, 관리자가 공유 대상을 정한 뒤 활성화한다. 기존 계정에 대한 권한을 임의 추정하거나 자동 부여하지 않는다.
3. 자동 전략 선택과 명시적 계정 ID 선택에 같은 접근 검사, 활성 상태, 자격증명 유효성 기준을 적용한다. 접근이 거부된 요청은 다른 계정으로 조용히 전환하지 않는다. 계정 목록과 사용 이력도 공유 범위와 관리 권한에 맞게 처리한다.
4. 기존 우선순위·라운드로빈·최소 사용 전략을 가능한 한 재사용한다. SIWC 계정의 성공·실패 및 사용량은 적합한 저장 구조에 기록하되, 기존 로그와 외래키를 보존하는 마이그레이션을 구현·검증한다.
5. 제공자의 사용 한도 또는 정책 제한 회피를 위한 무조건적 전환은 구현하지 않는다. SIWC를 통한 다인 공유의 제공자 정책 적합성은 별도 확인 사항이다.

## 대안 및 결과

- **모든 계정을 모든 사용자에게 자동 공유:** 설정은 간단하지만 기존 데이터에서 공유 의도를 추정하므로 채택하지 않는다.
- **소유자만 사용하도록 강제:** 접근 범위는 좁지만 관리자가 합의하에 계정을 공유하는 제품 목표와 맞지 않아 채택하지 않는다.
- **임시 수동 SIWC ID 선택만 유지:** 실제 계정 풀 전략과 접근 제어를 충족하지 못하므로 최종 방향으로 채택하지 않는다.

설정과 마이그레이션 복잡성이 증가한다. 기존 계정은 관리자가 공유 범위를 지정하기 전까지 일반 사용자가 사용할 수 없으며, 이에 대한 UI와 안내가 필요하다. 이는 설계 결정이며 구현 완료 또는 제공자 승인·약관 준수를 의미하지 않는다.

## 검증 기준

격리 DB에서 기존 자격증명 및 사용 이력 보존, 관리자 공유·해제, 전체 사용자 공유 및 특정 사용자 권한, 비활성 계정, 명시적 ID 우회 차단, 혼합 계정 전략 선택, 실패 시 다른 계정으로 무단 전환 방지 및 사용 기록을 검증한다. 별도 에이전트 리뷰 후 최종 테스트를 수행한다. 실제 사용자 계정이나 운영 DB는 테스트에 사용하지 않는다.
