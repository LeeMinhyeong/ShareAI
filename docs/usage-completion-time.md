# Usage completion timestamps

For a validated successful chat, the router samples wall time after durable attempt settlement and before publishing the terminal response, and independently samples monotonic `process.hrtime.bigint()` for elapsed milliseconds. Error outcomes are sampled before the usage writer. Ordinary requests actually dispatched upstream receive one best-effort failure row, including cancellations and 401/429, without error bodies or credentials; retries on the same account count as one logical request. Admission failures before dispatch produce no ordinary row. Successful requests do not also produce a failure row. Logging is not atomic with settlement or delivery; contention, writer failure or process crash can lose a row.

`UsageLogRepository.create` validates integer completion time in the JavaScript Date range and nonnegative safe-integer latency. Least-used counts completed successes from UTC midnight through the sampled as-of instant (inclusive), excluding later same-day records and malformed SQLite dates; SQLite CURRENT_TIMESTAMP and UTC ISO records are supported. Counts are separated by account kind and remain best effort, dependent on wall clock and log completeness. Quota reservation accounting and its clock are separate.

`tests/phase4-completion-clock.test.mjs` uses authenticated loopback requests, synthetic credentials, a private file database and a separate SQLite writer. It advances the wall clock across UTC midnight while the log writer is held, and includes a backward wall-clock jump before completion; the process timezone is America/New_York. Monotonic elapsed time is real, not a simulated precise duration.
